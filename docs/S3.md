# S3 in 0.5.0

The native app has a separate S3 backend. It uses the libcurl HTTP bridge also used by WebDAV, Foundation's XML parser, and CryptoKit for AWS Signature Version 4. No AWS SDK, CLI, Python or downloaded library is bundled. The Commander panes, file and folder queue, UTF-8 editor and reviewed one-way synchronization all reach this backend through `RemoteSession`.

## Connecting

Select **S3 · HTTPS** (port 443) or **S3 · HTTP** (port 80). Choosing S3 fills in `s3.amazonaws.com` when the host field is empty. Enter a host name, not a URL. For AWS, use the regional endpoint of your bucket (for example `s3.eu-central-1.amazonaws.com`) and the same **Region** in Advanced settings. An empty region means `us-east-1`. S3-compatible services such as MinIO work by entering their endpoint and port.

- **Access key ID** is stored in the saved site as its user name.
- **Secret key** and the optional **Session token** (for temporary STS credentials) stay in memory for the connection only. They are never written to site JSON, Keychain, URLs, command-line arguments or logs. The secret key is never transmitted; every request is signed.
- **Bucket / folder** is the initial path. `/` lists all buckets, which needs the `s3:ListAllMyBuckets` permission. Users with only bucket-level access should enter `/bucket-name` or `/bucket-name/folder`.
- **URL style** defaults to virtual-hosted (`bucket.host/key`). Path-style (`host/bucket/key`) is used when the toggle is on, when the host is an IP address or `localhost`, when the bucket name is not a DNS label, and for dotted bucket names over HTTPS (wildcard certificates cannot match them).

HTTPS requires TLS 1.2 or later, certificate-chain verification and hostname verification. A per-site PEM CA bundle supports private authorities without disabling checks. Redirects are never followed, and netrc and ambient proxies are not used. S3 over HTTP displays its unencrypted status: requests are signed, but file contents, object keys and session tokens travel in clear text.

When a bucket is in another region, AWS reports it in an error and the app shows the region to configure. It does not retry automatically or switch endpoints.

## Paths, folders and listings

The application path `/bucket/a/b.txt` maps to key `a/b.txt` in `bucket`. Folders follow the common S3 convention: listings use `ListObjectsV2` with delimiter `/`, `encoding-type=url` and continuation-token pagination (up to one million entries per folder in this preview). A zero-byte `folder/` marker object represents an empty folder; **New Folder** creates one with `If-None-Match: *`. Object keys are UTF-8, up to 1024 bytes.

Some valid S3 keys cannot be addressed as a path. These are **not shown**: keys with empty, `.` or `..` segments (such as `a//b` or `a/./b`), and keys containing control characters or backslashes. An object hidden by a folder of the same name (both `x` and `x/…` exist) is also not shown; the folder is shown instead. Recursive folder deletion still removes every key under the folder's prefix, exactly as listed by the server. Requests send the encoded path verbatim, so libcurl never collapses dot segments into a different key.

S3 has no POSIX permissions, owners or symbolic links. Rights show as unavailable and **Permissions…** is disabled. Modification times are the server's `LastModified`. Uploads cannot preserve the local mtime, so synchronization may propose the same unchanged file again, as with WebDAV.

## Writes, integrity and conflicts

- **Uploads up to 64 MiB** use a single `PUT`. The SHA-256 of the file is computed first, then sent as the signed payload hash and as `x-amz-checksum-sha256`. The server rejects the request if the bytes it receives differ, for example when the local file changes during transfer.
- **Larger uploads** use multipart upload with 16 MiB parts (more for very large files, to stay within 10,000 parts). Each part is SHA-256 signed. Cancellation, failure or a rejected completion aborts the multipart upload, so no parts are left behind.
- **No-clobber** writes send `If-None-Match: *`. **Approved replacement** sends `If-Match` with the reviewed or just-checked ETag. For multipart uploads, the condition is enforced on `CompleteMultipartUpload`. A destination created or changed after the client's own check makes the write fail with a conflict instead of overwriting it. Servers without S3 conditional-write support may ignore these headers. The client's pre-checks still apply, but the final guarantee then depends on the server.
- **Downloads** send `If-Match` with the listed ETag, write to a temporary file, verify the size, and verify the stored full-object SHA-256 when the server returns one. Composite multipart checksums are not verified, so those objects are checked by size and ETag only. The file is committed with the same no-replace/approved-replace rename used by the other protocols.
- **Rename** of a file is a server-side multipart copy. `UploadPartCopy` pins the source version with `x-amz-copy-source-if-match`, and `CompleteMultipartUpload` carries the destination condition. The copy preserves Content-Type, Cache-Control, Content-Disposition, Content-Encoding, Content-Language, Expires, storage class, SSE-S3/KMS settings and `x-amz-meta-*`. Rename refuses objects with non-ASCII metadata it cannot re-send unchanged. Tags, ACLs, object-lock settings and SSE-C objects are not preserved. The destination's ETag becomes a multipart ETag.
- The source is then deleted. S3 deletes are not conditional, so the client rechecks the source ETag immediately before deleting. A change in the remaining window can still be lost. **Folder rename is not supported**, because it would copy every object non-atomically.
- Buckets cannot be created, renamed or deleted from the app.

## Verification and limits

Integration tests run against two disposable MinIO containers (HTTP and HTTPS with a generated CA). They use test-only users: one with read-write access and one that can only list and read. See [VERIFICATION.md](VERIFICATION.md). Because MinIO locks an object for the duration of a PUT, a competing write cannot be injected mid-stream. The race tests therefore inject it after the client's checks and before the request, which exercises the server-side condition.

Not yet verified: AWS S3 itself, other S3-compatible services (Ceph RGW, Wasabi, Backblaze B2, Cloudflare R2, Garage and others), virtual-hosted addressing against a real DNS endpoint, region redirects, STS session tokens against a real service, very large or slow transfers, and keys with empty or dot segments (MinIO rejects them; listing behavior is covered by unit tests). Still missing: versioning, presigned URLs, storage-class selection, ACL/tag editing, SSE-C, requester-pays, bucket management, automatic region discovery, proxies, and resuming an interrupted multipart upload.
